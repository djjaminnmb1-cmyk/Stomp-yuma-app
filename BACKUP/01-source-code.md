# 01 · Source Code Inventory + GitHub Push Steps

## What "the source code" is

The `/app/` container holds two apps and their supporting docs:

```
/app/
├── backend/          FastAPI + Motor + MongoDB              2.8 MB
├── frontend/         Expo SDK 54 + expo-router + RN 0.81   875 MB (700 MB is node_modules)
├── memory/           PRD.md + test_credentials.md          224 KB
├── scripts/          One-shot admin scripts                <1 MB
├── tests/            Repo-level integration tests           small
├── test_reports/     Historical testing_agent output       376 KB
├── test_result.md    Testing protocol + main↔testing log    42 KB
├── design_guidelines.json  UI palette + typography          7.7 KB
├── auth_testing.md   Sign-in-with-Apple manual test matrix  3 KB
├── README.md         (basically empty)                     29 bytes
└── stompin-app.zip   OLD 191 MB snapshot — safe to ignore
```

**Ignore for backup**: `frontend/node_modules/` (regenerated by `yarn install`),
`frontend/.metro-cache/`, `frontend/.expo/`, `.ruff_cache/`, `stompin-app.zip`,
and the `mongo-dump/` / `mongo-json/` folders in this backup (they contain user PII).

## Step-by-step: push to your private GitHub

You can do this from the Emergent shell OR from a local machine after
downloading the folder. **Do not push `mongo-dump/`, `mongo-json/`, `.env`,
`.p8`, or `memory/test_credentials.md`**.

### Option A — push from the Emergent container (fastest)

1. **Create the repo on GitHub** (private, no README, no license, no gitignore —
   we already have all three).
2. Take note of the SSH URL (`git@github.com:<you>/<repo>.git`) or HTTPS URL.
3. Set your git identity in the container (one-time):
   ```bash
   git -C /app config user.email "you@example.com"
   git -C /app config user.name "Your Name"
   ```
4. Extend `/app/.gitignore` with the block above.
5. Add your GitHub SSH key OR use a Personal Access Token via HTTPS:
   ```bash
   # HTTPS with PAT (simplest):
   git -C /app remote add origin https://<PAT>@github.com/<you>/<repo>.git
   ```
   (The `<PAT>` is a fine-grained GitHub PAT with `repo` scope. Rotate after use.)
6. Stage and push:
   ```bash
   cd /app
   git add .
   git status                 # eyeball: no .env, no *.p8, no BACKUP/mongo-*, no memory/test_credentials.md
   git commit -m "Full snapshot — June 2026"
   git branch -M main
   git push -u origin main
   ```
7. Remove the token from the remote URL afterwards:
   ```bash
   git -C /app remote set-url origin https://github.com/<you>/<repo>.git
   ```

### Option B — download `/app/` first, push from your laptop

Use Emergent's built-in file browser or `scp -r` (if SSH access is enabled)
to pull `/app/` locally, then follow the same `git init && git push` steps
from your laptop. This is safer if you're new to git — you can inspect
`git status` in a familiar editor before committing.

## Building on a fresh machine after clone

```bash
git clone git@github.com:<you>/<repo>.git stompin-ground-yuma
cd stompin-ground-yuma

# Backend
cd backend
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp ../BACKUP/backend.env.example .env    # then fill placeholders

# Frontend
cd ../frontend
cp ../BACKUP/frontend.env.example .env   # then fill placeholders
yarn install                              # respects packageManager pin
```

See `05-restore-instructions.md` for the full cold-start playbook including
MongoDB and Apple `.p8`.
